CAD 3P Log Browser

Complete User Guide & Reference Manual

v4.0.10 .NET Framework 4.8 Windows

📚 Introduction

CAD 3P Log Browser is a professional log-file analyser built specifically for CAD application trace logs. It parses structured ENTER/EXIT markers, computes precise per-method timings, and gives you multiple interactive views — all inside a fast, virtual-mode UI that handles 500,000+ line files without breaking a sweat.

🌳 Analysis Views

  • Call Tree (hierarchical call stack)
  • API Tree (grouped by method)
  • Performance statistics table
  • Call Graph (dependency graph)
  • Timeline / Flame Graph (one tab, two modes)
  • Heatmap (API activity over time)
  • Thread View (side-by-side per-thread trees)
  • Exceptions (grouped by type + correlation ID)
  • AI Assistant (multi-provider)

📊 Key Capabilities

  • Virtual-mode log view (500 k+ lines)
  • Regex / multi-criteria filtering
  • Bookmarks with persistence
  • Error / Warning navigation
  • Dark & Light themes
  • Export to CSV, JSON, XML, PNG
  • Merge or side-by-side compare multiple log files
  • Drag-drop or command-line multi-file open
  • Lazy loading for huge trees

⭐ What’s New in v4.0

A large pass through the enhancement backlog — 26 fixes across nearly every part of the app, closing out real gaps found during a full feature-by-feature audit rather than cosmetic polish. Grouped by area:

📁 Files & Filtering

Dropping a file that doesn’t look like a log (wrong file grabbed by mistake) now asks before opening it instead of failing confusingly deeper in the parser. Opening a multi-entry .zip now prompts which entry to load instead of silently concatenating all of them together. The Filter dialog gained a real method-name term list (dropdown + Add, a list of terms, Remove / Remove All, wildcard support) that actually hides non-matching Call Tree / API Tree nodes — Time Range and Duration Threshold filters now hide non-matching nodes too, instead of only highlighting them. Log Level checkboxes disable themselves for levels the loaded log doesn’t have. Bookmarks gained a right-click Add/Remove on the log list and the Show Bookmarks list is now a real jump list (double-click or Go To) instead of a read-only dump.

🌳 Call Tree & Search

View → Hide Tabs collapses the whole right-side tab panel to give the tree full width, and whichever tree (Call Tree or API Tree) you last had active is now remembered across restarts. The tree search box gained Next/Previous navigation, a “N of M” match counter, and Escape to clear. Reload from Disk and Filter... are now on the tree’s own right-click menu too, not only the log panel’s.

🔌 API View & Performance

The API Invocation Details panel now shows a Total/Avg/Min/Max time summary. API Tree sorting gained Avg Time and Total Time modes plus an Ascending toggle, and now defaults to Count-descending. The API CSV export includes Total/Avg/Min/Max columns. Clicking a row in the Performance tab now selects that method in the API Tree, matching the other cross-navigating views. “Most Frequently Called” now draws a real proportional bar instead of Unicode block characters.

🔥 Visualizations

Clicking a flame graph bar now also selects the Call Tree node, and Timeline/Gantt zoom now scales vertically as well as horizontally. The Heatmap gained a Count-vs-Time colour toggle and its first export option (PNG). Call Graph export now captures the whole graph regardless of current zoom/pan, instead of only whatever was on screen.

🔔 Errors & Reporting

Help → Report Errors... is now a real dialog (recipient, steps to reproduce, the relevant crash log named) instead of just opening a GitHub Issues page. File → Export Analytics Report... is new — a styled HTML report (aggregate stats, top slowest, most called, call depth) that opens in your browser; Print → Save as PDF gets a PDF without a new dependency. Export Filtered Logs now confirms via the status bar instead of a dialog you have to dismiss, and every visualization export (Call Graph, Timeline, Flame Graph, Heatmap) now gets a timestamped filename so repeated exports don’t overwrite each other.

🧠 AI Assistant

Conversation history (both the Q&A flow and the chat assistant) is now capped instead of resending the entire unbounded history every turn. The AI Assistant chat gained example prompt chips. The AI Log Summarizer now feeds real per-method timing data into its analysis instead of only aggregate totals. Right-clicking the Call Tree gained Ask AI... (a natural-language question entry point at the tree itself) and Root Cause (this call)..., which analyzes one specific call using its actual parent chain rather than whole-log statistics, with results cached per call.

Previously in v3.1.9

🔄 Compare Logs

A full side-by-side log comparison tool, reachable from File → Compare Logs... (Ctrl+D) or by dropping exactly two files onto the window. Trees are colour-coded per difference type, scroll together, and a Performance Delta tab shows which methods got slower or faster between the two files. See Compare Logs.

🔥 Timeline and Flame Graph merged into one tab

The Timeline and Flame Graph views showed the same call data with almost identical chrome, so they are now one tab (“Timeline / Flame Graph”) with a mode-switch button pair at the top. Flame Graph aggregation was also fixed: repeated sibling calls to the same method now merge into a single wider bar labelled ×N, instead of drawing one sliver per call. See Timeline / Flame Graph Tab.

🔥 Heatmap rebuilt as a time-bucketed activity matrix

The Heatmap tab is now a genuine two-dimensional view — APIs on the vertical axis, fixed time buckets across the file’s span on the horizontal axis, colour depth showing how much time each API consumed within that window. This is the only view with both an API axis and a time axis. See Heatmap Tab.

🧠 Thread View tab

A new Thread View tab shows two independent call trees side by side, one per thread, selected from “Thread A” / “Thread B” drop-downs populated from the thread IDs seen in the log — useful for comparing what two threads were doing concurrently. See Thread View Tab.

🚨 Exceptions tab

Groups every exception seen in the log by type (with first/last-seen line numbers) and separately groups lines by correlation / request ID, so you can pull every log line tied to one request together. See Exceptions Tab.

📁 Multiple files: drag-drop dialog, and command-line support

Dropping 2+ files onto the window (or passing them on the command line) now offers a choice — Merge All, Compare (only offered for exactly 2 files), or Open First File Only. Command-line arguments are validated up front with every problem reported together (missing file, folder instead of a file, access denied, etc.), not just the first one encountered. See Opening Multiple Files.

📂 Recent Files moved to their own file

The recent-files list now lives in %AppData%\CAD3PLogBrowser\recentfiles.json instead of inside settings.json, so it survives a settings reset. Existing recent files are migrated automatically the first time you run this version.

🔄 Configurable auto-reload, off by default at 0

View → Watch for File Changes toggles disk-change monitoring, and a new Auto-reload after (seconds) setting (Settings → Files & Behavior) lets a changed file reload itself silently after a delay. Reloading is always non-blocking: at 0 (the default) the status bar shows a “File changed on disk — click to reload” message you click when ready; above 0 it reloads by itself after a silent countdown, also shown in the status bar.

🌟 Expand to Level (tree)

The Call Tree and API Tree context menus (and the Edit menu) gained an Expand to Level... command that expands every node down to a depth you choose in one step, collapsing anything deeper — a middle ground between one node at a time and Expand All. See Expand to Level.

🧠 AI Assistant: multiple providers, including self-hosted Ollama

The AI Assistant now supports several providers from one Settings page: Anthropic Claude, GitHub Copilot, and self-hosted Ollama (plus a Mock provider for testing without any network calls). OpenAI, Azure OpenAI, and Google Gemini are listed as Coming Soon — the settings fields exist but those three providers aren’t wired up to make requests yet. A long-standing bug where the Ollama server URL (and several other AI settings) silently reset to the default on every save has also been fixed. See AI Assistant Tab.

📝 Earlier in the v3.1 line: automatic update checks, ENTER/EXIT counting fixes in the API Tree, a redesigned Settings dialog, corrected toolbar icons, and theme-switching performance improvements. These are all still current — see Auto-Update and Settings Dialog for details.

🚀 Getting Started

Opening Your First Log File

📁 File → Open Press Ctrl+O, click the Open toolbar button, or drag & drop a .log file onto the window.
📁 Drop multiple files Drop 2 or more files (or pass them on the command line) to choose Merge, Compare (exactly 2 files), or open just the first one. See Opening Multiple Files.
🕐 Recent Files The last 10 files appear under File → Recent Files. Click any entry to reopen immediately.
🔄 Merge or Compare File → Merge Logs... (Ctrl+M) merges 2+ files into one time-sorted view; File → Compare Logs... (Ctrl+D) opens the side-by-side diff tool.
💡 Tip: Set the environment variable PTC_LOG_DIR to your log directory. The Open dialog will default to that folder automatically (or set a folder explicitly in Settings → Files & Behavior).

Recommended First Steps

  1. Open a log file (Ctrl+O).
  2. Press F8 a few times to scan through errors.
  3. Switch to the Performance tab and sort by Total (ms) to find the slowest methods.
  4. Click any tree node on the left to jump to that line in the log.
  5. Use Ctrl+I to filter the log down to interesting lines.

🌳 Call Tree

The Call Tree shows method invocations as a nested hierarchy, exactly mirroring the call stack at runtime. Activate it with the Call Tree toolbar button or View → Show Call Tree.

Lazy Loading

For very large call trees, the tree uses lazy loading: child nodes are populated on demand when you expand a parent. A “Loading…” placeholder is shown until children are rendered. The node-count threshold that triggers this (default 50,000) is configurable via Settings → Files & Behavior as Lazy-load tree above — lower it on slower machines for snappier expansion, or raise it to always build small/medium trees eagerly.

🔎 Tree Search

The text box at the top of the tree panel filters nodes in real time as you type.

  • Nodes whose text matches are highlighted in yellow.
  • Parent nodes that contain a match are automatically expanded and shown with a transparent background.
  • Non-matching leaf nodes are collapsed.
  • Clear the box to restore the full tree.
💡 Tip: The search is case-insensitive and matches any substring of the node label, including the duration suffix (e.g. typing 142 finds nodes labelled [142 ms]).

Command-Line Open

Pass one or more file paths as command-line arguments (e.g. from a shortcut, script, or another tool launching the browser). Every path is validated before anything opens:

  • Blank arguments are silently ignored.
  • A path that’s a folder, doesn’t exist, is access-denied, too long, or otherwise unreadable is reported by name — and every problem is collected and shown together in one message, not just the first one found.
  • One valid file opens directly, no dialog.
  • Two or more valid files show the same Merge / Compare / Open First dialog as drag-drop, above.
📝 Note: if some paths fail validation but at least one succeeds, you still get a warning listing what failed, then the valid file(s) proceed normally.

🔁 Auto-Update

How It Works

On every startup (subject to the configured interval) the app silently downloads a small JSON manifest from GitHub and compares the remote version with the installed assembly version. If a newer version is found the Update Available dialog appears.

Update Available Dialog

ButtonAction
Update NowDownloads the new Cad3PLogBrowser.exe to a temp folder with a live progress bar, then writes a batch script that replaces the EXE after the app closes and restarts it.
LaterDismisses the dialog. The next automatic check runs after the configured interval.
Cancel DownloadAppears while downloading. Aborts the transfer; the partial download is deleted.

Manual Check

Go to Help → Check for Updates at any time. A “Checking for Updates…” progress indicator appears in the status bar while it runs (the fetch can take several seconds, especially with retries on a slow connection). The result is always shown: the update dialog if a newer version is available, an “up to date” message if not, or a distinct error message if the check itself fails (e.g. no network access) — failure is never reported as if it were up to date. Help → View Update Log... shows the history of past update checks.

What Gets Replaced

Only Cad3PLogBrowser.exe is replaced. The following are not touched:

  • Help\UserGuide.html (and its Help\images\ folder) — ship the updated Help folder as part of the GitHub Release zip if you change the guide.
  • Cad3PLogBrowser.exe.config — .NET runtime binding config; rarely changes.
  • %AppData%\CAD3PLogBrowser\settings.json and recentfiles.json — all user preferences and recent files are preserved.
⚠ Note: The self-replacement uses a temporary .bat script launched via cmd.exe /C. If your environment blocks batch scripts (e.g. AppLocker), the update will fail with an error. In that case download and replace the EXE manually from the GitHub Releases page.

💡 Tips & Best Practices

Finding Performance Bottlenecks

  1. Open the Performance tab.
  2. Click Total (ms) to sort descending.
  3. The top rows are your most expensive methods — focus there first.
  4. Check Self (ms): a high Self value means the method itself is slow, not its children.
  5. Switch to Flame Graph mode (inside the Timeline / Flame Graph tab) to see the call-stack context of the bottleneck visually.
  6. For a time dimension, check the Heatmap tab to see when the API was busiest.

Investigating an Error

  1. Press F8 to jump to the first error, or check the Exceptions tab for a grouped overview.
  2. Press Ctrl+B to bookmark it.
  3. Press Ctrl+G if the error is inside a method call to jump to the surrounding ENTER/EXIT context.
  4. Right-click the enclosing tree node and choose Save Branch to extract just that call’s log lines for a bug report.

Comparing Two Runs

  1. Drop the two files onto the window together, or use File → Compare Logs... (Ctrl+D).
  2. Turn on Ignore timestamps and durations in Comparison options if you only care about structural changes.
  3. Use F7 / F8 to step through differences one at a time.
  4. Check the Performance Delta tab to see which methods got slower or faster between the two runs.

Narrowing Down a Large Log

  1. Press Ctrl+I to open the Filter dialog.
  2. Add a Time Range to focus on the incident window.
  3. Add a Text filter for a relevant module or method name.
  4. Combine with a Log Level filter of ERROR or WARNING.
  5. The status bar shows how many lines match; iterate until the count is manageable.

Cross-Referencing Trees

  • Select a node in the Call Tree → right-click → Show in API Tree to see all occurrences of that method.
  • Select a node in the API Tree → right-click → Show in Call Tree to see one occurrence in full call-stack context.
  • Use Expand to Level... to get a consistent overview depth on both trees at once.

Using Bookmarks Effectively

  • Mark the start and end of a slow period with Ctrl+B.
  • Use F2 / Shift+F2 to cycle through just those anchors.
  • Bookmarks survive file reloads — you can bookmark, reload, and continue where you left off.

🛠 Troubleshooting

File won’t open

Symptoms: Error dialog on open, or file shows 0 lines.
Fixes: Check file is not locked by another process. Verify it is a plain-text (or supported .gz/.zip) file, not some other binary format. Check read permissions. Try copy-pasting the file first.

Application is slow with a very large file

Note: Virtual-mode rendering means the log view itself should always be fast. Slowness usually comes from building the call tree for logs with millions of API calls. Use Ctrl+I to filter the log before loading trees, or enable lazy loading (automatic for > 50,000 nodes).

Tree is empty after loading

  • The parser looks for lines containing [ENTER] and [EXIT] markers. If your log format uses different markers, the tree will be empty.
  • Check that the log is the raw trace output and not a filtered/truncated copy.

Bookmarks or recent files not restored on reopen

  • Bookmarks are keyed to the full file path. If you moved or renamed the file, bookmarks are not found.
  • Check that %AppData%\CAD3PLogBrowser\ exists and is writable — both settings.json and recentfiles.json live there.

Theme toggle not working

  • Press Ctrl+T, or use View → Dark Mode — if either works but the toolbar button doesn’t, the toolbar icon may not have been created yet (check Settings for icon size).
  • Try opening Settings and re-selecting the theme there.

AI Assistant returns no results, or a provider seems unavailable

  • In Mock mode: a file must be loaded first.
  • In Anthropic / GitHub Copilot / Ollama mode: verify the API key or Server URL in Settings, check connectivity, and use Test Connection to confirm.
  • OpenAI / Azure OpenAI / Google Gemini are listed in the provider drop-down but are not yet functional (“Coming Soon”) — selecting one won’t send any requests.

Compare Logs shows no differences but the files look different

  • Check the Comparison options (Settings, or the dialog’s own Options button) — Ignore timestamps and durations is on by default and may be hiding the only differences present.
  • Make sure Synchronize Scrolling hasn’t scrolled you past the difference — use F7/F8 or First/Last Difference to navigate directly.

Expand All / Expand to Level hangs

  • For very large trees, this may take a moment. A progress message appears in the status bar.
  • Press Esc or click the status bar to cancel the operation.

Resetting to defaults

Delete %AppData%\CAD3PLogBrowser\settings.json and restart. Most settings (window state, theme, font, bookmarks) will be recreated with defaults. Recent files are stored separately in recentfiles.json in the same folder — delete that too if you also want to clear the recent-files list.

❓ FAQ

What log file formats are supported?

Any plain-text file, plus .gz and .zip archives (decompressed automatically). The parser auto-detects timestamp format and looks for [ENTER] / [EXIT] markers.

How large a file can I open?

The virtual-mode list view handles files with 500,000+ lines smoothly. Call-tree building becomes slower above ~200,000 API calls; use filtering first to reduce scope.

Can I open multiple files at once?

Yes — drop 2 or more files onto the window, or pass them on the command line, to choose Merge (combine into one time-sorted view), Compare (side-by-side diff, exactly 2 files), or open just the first one. See Opening Multiple Files.

What’s the difference between Merge and Compare?

Merge combines 2+ files into a single interleaved, time-sorted log you browse normally. Compare keeps the two files’ call trees separate, side by side, and highlights exactly what’s different between them — it only works with exactly two files.

Where are my settings saved?

Settings: %AppData%\CAD3PLogBrowser\settings.json. Recent files: %AppData%\CAD3PLogBrowser\recentfiles.json.

How do I configure the default open directory?

Set the PTC_LOG_DIR environment variable, or set a custom path in Options → Settings → Settings → Default open folder. The env variable takes precedence unless a custom path is also set.

Can I use the Flame Graph or Heatmap without an internet connection?

Yes. The Flame Graph, Timeline, Heatmap, Call Graph, and all other visualisations are rendered locally with no network access required. A self-hosted Ollama AI provider also works fully offline (or on a private network) — only Anthropic, GitHub Copilot, “Check for Updates”, and “Report Errors” require internet.
